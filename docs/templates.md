# Generating a template and getting it onto the device

## Generate

```sh
snif gen daily -o ~/archive/templates \
  --title "Daily plan" --theme dots \
  --date   "due:2026-2030:label=Due date" \
  --radio  "prio:low,mid,high:label=Priority" \
  --slider "mood:0:10:step=0.5:label=Mood" \
  --check  "done:label=Done today" \
  --button "submit:label=File this page" \
  --input  "notes:style=lines:w=1400:h=520:label=Notes"
```

writes two files:

```
snif-daily.png    # 1920x2560, 8-bit greyscale — import this on the device
snif-daily.yaml   # the snorg templates: section — pass to either tool with -c
```

Widget flags are laid out **in the order given**, stacked down the page as bands
(a caption line and a body). One micro-syntax for all of them: a name, then
`:`-separated tokens — a token holding `=` is an attribute, anything else is
positional.

| Attribute | Applies to | Meaning |
|---|---|---|
| `label=` | any | the caption drawn for the widget |
| `labels=` | `--radio` | per-option labels (default: the option keys) |
| `style=` | any | background inside the widget's writing area |
| `w=` `h=` | any | the body's pixel size — how an input field is dimensioned |
| `step=` | `--slider` | the value snap |

`--figure NAME[:ATTR…]` places an area to draw in rather than a field to fill:
a plain snorg box, never analyzed, whose rect a consumer crops the drawing out of
(`docs/widgets.md`). It takes `label=`, `style=`, `w=` and `h=` like anything else
and defaults to the full content width and 1200px tall.

Themes, page-wide (`--theme`) or per widget (`style=`): `blank`, `dots`, `grid`,
`lines`. A measured area is cleared to white before its own style is drawn, so a
page can carry a dense pattern without making its tick boxes noisy.

Escape a `:` inside a caption as `\:`.

## Wiring it into the config

The generated YAML is a `templates:` section; nothing loads it until a config that
is already loaded pulls it in. The XDG user config is the only file either tool
loads on its own, so chain it to the archive once:

```yaml
# ~/.config/snorg/config.yaml — loaded automatically
archive: ~/archive
include: [~/archive/config.yaml]
```

```yaml
# ~/archive/config.yaml — provider credentials and the forms
include: [templates/snif-daily.yaml]
```

After that both tools run with no globals at all. Include paths are relative to the
file listing them, and an include's keys win over its includer
(`snorg/docs/config.md`).

A `templates:` list is **replaced** by a later layer, never appended to, so a second
template cannot simply be a second include — only the last one would stay
configured. Declare every template in one file: paste the generated `templates:`
entries into `~/archive/config.yaml` instead of including two of them.

## The header is the source

The YAML's header records the canonical command that produced it:

```yaml
# snif template "daily"
# generated by snif v0.1.0 — re-render rather than editing by hand
# command: snif gen daily --title 'Daily plan' --theme dots --date 'due:2026-2030:label=Due date' …
# re-render: snif gen -f snif-daily.yaml
```

`snif gen -f snif-daily.yaml` re-runs it and rewrites both files in place. That is
where styles and themes live — they matter only while drawing, so they need no
runtime home. Output is **deterministic and carries no timestamp**: regenerating an
unchanged template rewrites the same bytes, so a template under version control
never churns.

Editing a rect in the YAML by hand is fine — snif reads what the file says — but
the next `-f` re-render replaces it. Change the command, not the output.

## Importing, and the hash problem

snorg selects a template by the **sha256 of the page's decoded background**
(`snorg/docs/templates.md`), so the file the config names must hash to exactly what
the device stores. snif generates the device's own form — 8-bit greyscale,
non-interlaced, no ancillary chunks, nothing but `IHDR`/`IDAT`/`IEND` — which is
the best possible starting point, but nothing guarantees a tablet imports a PNG
byte for byte. A re-encode on import leaves a template that quietly matches no
page.

Fix it from the evidence:

```sh
# 1. copy snif-daily.png into the device's template folder, draw on a page, export
snorg -a ~/archive ingest daily.note
snorg -a ~/archive query all | tail -1                 # the PAGEID you just drew
snif  -a ~/archive -c ~/archive/templates/snif-daily.yaml \
      bind <PAGEID> ~/archive/templates/snif-daily.png
```

`bind` copies that page's stored background over the generated image. The config
keeps its `image:` path; the path now holds the bytes the device writes, so every
page drawn on that template matches. It does nothing when the template already
matches.

## Reading

```sh
snorg query templated | snif read        # config chained as above
```

`input` widgets need snorg's vision model. `read` transcribes a page whose input
boxes have never been analyzed (provider credentials in the config); `--no-analyze`
stays offline and reports them as unanalyzed instead. A form with no `input`
widget never builds a provider at all.
